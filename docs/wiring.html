FT2232H GPIO link between two Orcraft endpoints

Two Mini Modules, one on each machine, channel A only. Six signal wires straight across plus a shared ground. Which side drives which pin follows who is sending, so the same wires carry messages both ways.

Handshake per nibble

Sender puts the nibble on DATA and raises REQ. Receiver reads DATA and raises ACK. Sender lowers REQ. Receiver lowers ACK. Each machine polls its USB port at its own speed, so the wires never outrun the slower side. A frame is one length byte followed by the UTF-8 bytes of the message.

Before the two-machine tests

Run LED Blink and LED Pattern on each machine first: they drive the six LEDs of that module on AD0-AD5 and read every write back, which proves the driver, the module and the power jumpers without the second machine taking part. The same wiring serves every test of the suite.

Module setup

Bus power takes five short jumpers on the module: CN3-1 (VBUS) to CN3-3 (VCC) so the chip enumerates, then CN2-1 to CN2-11, CN2-3 to CN2-21, CN2-5 to CN3-12 and CN3-12 to CN3-22, which feed the I/O pins from V3V3; without those the pins stay low. The suite installs pyftdi and libusb-package into the endpoint's Python from its requirements file; on Windows the module's interfaces are switched to WinUSB once with Zadig.
